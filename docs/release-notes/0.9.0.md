# Life Manager 0.9.0

0.3.3 から、git の作業（変更の記録・ブランチ・GitHub への送信）をアプリの画面で行えるようになりました。実行される git のコマンドも画面に出るので、使いながら git を学べます。
タスク管理には、表での一覧・見積もり・分析・サブイシュー・スプリント（バーンダウン・ベロシティ）などが加わりました。
GitHub のアカウントがない人の入口と、チームへの招待（送る・受ける）もアプリに入れました。「GitHub でログイン」で、トークンを作らずに、選んだリポジトリだけを期限つきで許可して入れます。

## 主な新機能

### git の作業（PC）

- サイドバーの「作業」で、取り組む Issue を選び、ブランチ・コミット・プッシュ・完了までを順に進められます。上の 1 行の段（Issue → ブランチ → 変更 → コミット → プッシュ → プルリク → マージ → 完了）を押すと、その段の画面に切り替わります。
- 作業は Issue から始めます。自分の担当でない Issue は「自分に割り当てて始める」で自分が担当に入り、始めると「状態:進行中」になります（Issue を選ぶ前はコミットできません）。
- 「ブランチ」画面で、ブランチごとのコミットの履歴を、左右に移りながら見られます（← → キーやマウスホイールでも移れます）。
- 「全体図」で、ブランチが分かれて合流する様子を 1 枚の図で見られます（見せ方は「ラベル」と「線」から選べます）。
- コミットやブランチの「⋯」か右クリックで、マージ・リベース・チェリーピック・リバート・リセット・タグなどを行えます（元に戻せない操作は、確認の画面を出します）。
- どの操作でも実行される git のコマンドが画面に出て、ステージやコミットの意味の解説も出ます（「設定 → 表示」の「学習の補助」で消せます）。
- 競合したときは、作業タブで競合したファイルを直して先へ進めるか、中止して始める前に戻せます。
- 作業タブのファイルを右クリックして、そのファイル・拡張子・フォルダを .gitignore で無視でき、「.gitignore を編集…」で直接書き換えることもできます。
- 左上のリポジトリの「＋ リポジトリを追加…」で、GitHub の URL を貼ってリポジトリを追加し、置き場所を選んでクローンできます。
- 同じ画面の「GitHub にまだ無い → 手元のフォルダを GitHub に上げる」で、課題や作品のフォルダを 4 つの手順で GitHub に上げられます。
- Git が入っていない PC では、インストールのときか起動したときに案内が出て、Git とコミットに使う名前・メールアドレスをその場で用意できます。
- 作業フォルダを決めていない PC でも、「ブランチ」「全体図」で GitHub にある履歴を見て、コミットの「変更内容を見る」を使えます。

### プルリク

- サイドバーの「プルリク」で、プルリクの一覧（開いている・マージ済み・閉じた）と、会話・変更されたファイル・コミットを見られます。
- 「変更されたファイル」で、どのファイルをどう変えたかを、行番号つきの差分で見られます（1 列と、左右に並べるの切り替え。見終わったファイルに「見た」の印）。行にマウスを乗せて ＋ で、その行にコメントできます。
- 承認する・修正を依頼する・コメントする、レビューをお願いする人を足す・外す、題名と説明の編集、下書きの切り替え、閉じる・開き直すができます。
- マージの箱で、マージできるか（競合・保護ルール・下書き）と、マージの仕方（マージコミット・スカッシュ・リベース）の違いと手元でするときのコマンドが出ます。マージしたら GitHub のブランチを消して片づけ、あとで戻すこともできます。競合しているときは「この PC で直す」で、作業タブの「競合を直す」につながります。
- 「＋ プルリクを作る」で、入るコミットと変更を確かめてから作れます。つなげる Issue を選ぶと、題名と `Closes #N` が入ります。
- 作業タブの流れに「プルリク」「マージ」の段を足しました（Issue → ブランチ → 変更 → コミット → プッシュ → プルリク → マージ → 完了）。プルリクを作ると、つないだ Issue が「状態:チェック待ち」になります。プルリクにしないときは「今回はプルリクしない」で、すぐ完了にできます。

### Actions

- サイドバーの「Actions」で、テストやビルドの失敗とセキュリティのお知らせを、**直す順に積んで**見られます（🔴 すぐ直す → 🟠 早めに → 🟡 手が空いたら → ● 待つだけ）。いちばん上の帯で件数がひと目でわかり、サイドバーには 🔴・🟠 の数が出ます。
- 1 枚はワークフロー × ブランチの最後の結果です。同じ失敗が続くと重ねて「×3 続けて」、直すと「✔ 直りました」と出て山から消えます。
- カードを押すと、何をすればよいか・ジョブとステップ・失敗したステップのログ（エラーのまわりだけ、赤い行）が出ます。もう一度実行・止める・手で実行（workflow_dispatch の入力つき）もできます。
- Dependabot（古くて危ないライブラリ）とコードスキャンのお知らせも、危険度に合わせて同じ山に入ります。
- 非公開のリポジトリでは、Actions は**オフが既定**です（まだ使っていないリポジトリは、持ち主の Life Manager がオフにします）。オンにする・もう一度動かす・手で実行するときは、持ち主の無料の時間（月 2,000 分）を使うことを**毎回確かめ**、操作できるのは**持ち主だけ**です。今月このリポジトリで動いた時間の目安も出します。ひな形には、時間の上限と、同じブランチの前の実行を止める設定が入っています。
- プルリクの一覧・詳細（「チェック」タブ）・マージの箱に、チェックの結果が出ます。「ログを見る」で Actions のそのジョブが開きます。
- GitHub の側で準備がいるときは「はじめる準備」で促します。ワークフローがなければ、言語に合うひな形（1 行ずつ説明つき。Unity のテスト〔GameCI〕・Unreal の自動テスト〔Unreal の入った PC をランナーにする〕も）を作業フォルダに置けます。Dependabot を有効にする（管理者）、足りない権限を承認する画面を開く（メンバーは持ち主に送る文をコピー）もできます。

### リリース・アクティビティ

- サイドバーの「リリース」で、リリースの一覧（最新・試用版・下書き）と、ノート・添えたファイル（ダウンロード数）を見られます。
- 「＋ リリースを作る」で、マイルストーンの閉じた Issue から、ノート（新しい機能・直した不具合・そのほか・手伝った人）を自動で作れます（GitHub のプルリクから作る・自分で書くも）。タグ・下書き・試用版・最新・ファイルを添える（インストーラー・latest.json など）・マイルストーンを閉じるまで、1 つの画面でできます。
- サイドバーの「アクティビティ」で、「あなたがすること」（レビューを頼まれた・修正を頼まれた・自分のプルリクのチェックの失敗・担当の期限・名前を呼ばれた など）と、チームの動き（日ごと）を見られます。GitHub の通知の代わりです（GitHub の決まりで、App からは通知を読めないため）。

### タスク

- 「カード｜表」で、一覧を表（1 行に 1 件）でも見られます。
- 「まとめる」で、親子・状態・優先・分野・担当・マイルストーンごとにまとめて見られます。
- 「並び」で期限が近い順などに並べ替えられ、カードには期限（「あと 12 日」など。過ぎると赤）が出ます。
- 絞り込みを「フィルタ」ボタンにまとめました。ラベルを複数選んで「どれか（OR）」と「すべて（AND）」を切り替えられ、マイルストーンや見積もりでも絞れます。
- 「保存した見方 ▾」で、絞り込み・並び・まとめ方に名前を付けて保存し、チームの全員で同じ見方を使えます。
- 「☑ 選ぶ」で複数の Issue を選び、完了・状態・ラベル・見積もり・マイルストーン・担当をまとめて変えられます。
- Issue の詳細の「📏 見積もり」でタスクの大きさを付けられ、合計が一覧・ボードの列・マイルストーンに出ます（単位は「設定 → タスク」の「見積もりの単位」で、ポイント・時間・日・人月から選べます）。
- サイドバーのタスクの一番上の「📈 オーバービュー」で、期限切れ・担当ごとの数と見積もり・8 週の流れなど（いまの状況）と、チームのペースを見られます。マイルストーン・担当・分野で絞り込めます。
- Issue の詳細の「サブイシュー」の欄で、大きな Issue を子の Issue に分けられます（GitHub のサブイシューと同じ親子になります）。
- Issue を作るときに「テンプレート」を選ぶと、題名の頭・本文・ラベルが入ります（テンプレートがなければ、見本を「このリポジトリに置く」で置けます）。
- 「＋ 関連を足す」で意味の近い Issue どうしを結べ、「クローズ ▾」で完了・予定なし・重複の閉じ方を選べます。
- 「コメントと変更の履歴」に、ラベル・担当の変更や、ほかの Issue・コミットから触れられたことが、時間の順で出ます。

### ボード

- ボードを「📥 未整理」と「🔥 着手済み」の 2 つに分け、状態ごとに別の板を掛けました。付箋をドラッグして別の板に貼り替えると、状態が変わります（もう一方のタブに落とすと、そちらのボードへ移ります）。
- 見た目を クエスト・ホワイトボード・黒板 から選べます（ボードの上か「設定 → 表示」）。
- 付箋に、担当・期限切れ・「✏️ 作業中」・つないだプルリクの進み（🔃 #2 レビュー待ち など。押すとプルリクが開きます）が出ます。
- 区画をどちらのボードに置くか・並びは、「設定 → タスク」の「ボードの区画」で決めます（チームで共有します）。

### マイルストーン（スプリント）

- マイルストーンを、期間を区切った作業のまとまり（スプリント）として使えます。開始日は「編集」で決めます（説明の最後に「開始: 2026-09-28」と書かれ、GitHub の画面でも読めます）。
- カードを開くと「バーンダウン」で、残りの量が日ごとにどう減ったかと、このペースで終わる日（期日より遅れそうなら赤）が分かります。
- オーバービューの「チームのペース」で、終わったマイルストーンごとに終えた量（ベロシティ）と、次のスプリントに入れる量の目安が分かります。
- 同じ所で、「状態:進行中」にしてから閉じるまでの日数（サイクルタイム）も分かります。量は「見積もり｜件数」で数え方を選べます。

### ガント

- 日程がなく見積もりのある Issue を、見積もりから仮の帯（点線）で置きます（同じ担当の帯は重ならないように置きます）。
- 仮の帯を押して「この日程で決める」を選ぶと、その日程を Issue に書き込めます（「見積もりから仮の日程を置く」を外すと、仮の帯は出ません）。
- マイルストーンの期限に赤い点線が出て、期限を超える仮の帯の部分は赤くなります。
- 帯の色は「設定 → 表示」の「ガントの帯の色」で変えます。

### チーム

- 「GitHub でログイン」で、トークンを作らずに、自分の GitHub のアカウントで入れます（ブラウザで GitHub に出るコードを入れて許可するだけです）。
- Life Manager が触れるのは、持ち主が Life Manager を入れて選んだリポジトリだけです。チームのリポジトリには、リーダー（組織なら組織の持ち主）が一度だけ Life Manager を入れます。セットアップの「使用するリポジトリを選ぶ」は、GitHub の画面をあなたのアカウントを選んだ状態で開くので、Install を押すだけです（2 つ目からは「リポジトリを追加する」）。「作ってはじめる」で、リポジトリを作ってそのまま始められます。
- ログインの鍵は 8 時間ごとに自動で新しくなり、ログインのときに選ぶ「この PC で使う期限」（30 日・90 日・半年）が来ると、もう一度ログインします。期限が近づくと、画面の上で知らせます。GitHub の側の変更で鍵が期限の前に使えなくなったとき（アプリの権限を足したときなど）も、自動で新しくして続けます。設定 → トークン に、今の鍵がいつまでか・前に新しくした結果が出ます。
- 起動すると、まず GitHub へのログインです。アカウントがない人は、ここで「GitHub で作る」から作れます。
- ログインすると、「チームを作る」「招待を受ける」「個人で使う」から使い方を選びます（招待が届いていれば、「招待を受ける」に印が付きます）。次の画面には、選んだものだけが出ます。
- 「招待を受ける」では、自分の GitHub の名前が大きく出ます。メンバーはこの名前をリーダーに伝え、届いた招待のメール（かリーダーから届いたリンク）で参加すると、アプリが自分で気づいて「このリポジトリではじめる」が出ます。
- リーダーは「設定 → 接続」の「案内をコピー」で、メンバーに送る「参加の案内」をコピーできます。
- 「チームを作る」「個人で使う」では、先に「もうあるリポジトリを使う」か「新しく作る」かを選びます。新しく作るときは「作る → Life Manager に許可（作ったリポジトリだけ）→ この PC に持ってくる」の順に進みます。チームを作ったときは、はじめると「設定 → 接続」が開き、そのまま招待できます。
- リーダーは「設定 → 接続」で届いた名前をまとめて貼って「招待を送る」ことができ、送った招待の「取り消す」「送り直す」も行えます。メンバーを「外す」こともできます（その場で確かめてから外します）。

### つながらないとき（オフライン）

- インターネットにつながらないときも、最後に読み込んだ Issue・設定・日誌を見たり、変えたりできます。
- 変えた内容は送信待ちになり、つながったら順に GitHub に送ります（上のバーに「オフライン」「未送信」が出ます）。
- つながらないあいだに作った Issue には「仮1」のような番号が付き、送ると GitHub の番号に変わります。
- GitHub 側でも同じところが変えられていたときは「確認」に並び、「GitHub の内容を残す」「自分の変更で上書き」などから選べます。

### 表示

- 「設定 → 表示」の「サイドバーの位置」で、サイドバーを左・右・上・下から選べます。
- サイドバーの「たたむ」（Ctrl+B）で、サイドバーを隠して画面を広く使えます（画面の端にマウスを寄せると出てきます）。
- サイドバーの一番下に、ログインしているアカウント（アイコン・名前・期限）が出ます。押すと、アカウントの切り替え・名前のコピー・GitHub のページ・ログインとトークン・ログアウトのメニューが開きます。
- 1 台の PC で、いくつかの GitHub のアカウントを切り替えて使えます（アカウントのメニュー →「アカウントを切り替える」）。アカウントごとに、使うリポジトリの一覧を覚えます。ログアウトしたあとに別の人が使っても、前の人のリポジトリは一覧に出ません。
- 左上のリポジトリを押すと一覧が開き、切り替え・この PC のフォルダ（選ぶ・クローン・エクスプローラーで表示）・一覧から外すができます。一番下の「＋ リポジトリを追加…」で、GitHub にある／この PC にある／新しく作る から選んで追加できます（GitHub Desktop のように）。
- 設定の区分を「接続（チーム）・タスク・通知・表示・トークン・その他」にしました。プロジェクト管理・作業フォルダは左上のリポジトリへ、Git の確認は「その他」へ移りました。ボードの区画・ボードの見た目・ガントの帯の色も設定にまとめました。
- 「設定 → その他」の「バージョン」で、新しいバージョンがあるかを確かめて更新できます。Actions の「今は使わない」で隠した勧めも、ここで戻せます。
- ガントは、はじめて開いたとき、いちばん近い開いたマイルストーンを出します。
- メモの投入は、画面の角の 📝 か Ctrl+M から（どの画面からでも）。📝 の場所は「設定 → 表示」で右上・右下・左上・左下・隠す（Ctrl+M だけ）から選べます。サイドバーや上のバーにはかぶらず、たたんだサイドバーが出てくると押し出されて動きます。ほかの欄で文字を打っているあいだは、画面の外へよけます。分野は、そのリポジトリの「分野:」のラベルから選びます。
- 画面の動きを増やしました。動いた向きで動きが変わります（縦のサイドバーや一覧は上下、タブや横の帯は左右、作業 ⇄ ブランチ ⇄ 全体図とカード ⇄ 詳細は寄る・引く・ふくらむ）。サイドバーの印は次の画面へすべり、画面ごとの色になります。完了すると、キラキラとスタンプ（はんこ・先生のはんこ・英語のバッジ・絵文字から毎回ひとつ）と「✨ #45 を完了しました」の知らせが出ます。新しく入ったカード・表の行は、光ってキラキラします（表の行には「NEW」）。「設定 → 表示」の「画面の動き」で少なめにもできます。
- 競合（コンフリクト）が起きると、どの画面にいても 1 回だけ知らせが出て、何が起きたか・どのファイルか・直し方が分かります。作業タブで競合のファイルを選ぶと、マージツール（か所ごとに今のブランチの方・取り込む側・両方・自分で書く を選ぶ）で直せます。使う側と捨てる側は、はっきり分けて出します。
- Issue の詳細の本文に、ガントの日程などの見えない印（`<!-- gantt:… -->`）を出さないようにしました。本文を直すときも欄に出さず、保存するときにそのまま残します。
- タスクの上は、1 行目を検索と絞り込み、2 行目を見せ方と件数・更新・作るにまとめました。表のときは窓の横いっぱいに広がります。
- PC の「タスク」は、左に一覧・右に選んだタスクの詳細を出します（カードのとき。↑↓ で上下のタスクへ、境目をドラッグして幅を変えられます）。表のときや窓が狭いとき、スマホは、今まで通り詳細を重ねて出します。
- アプリのアイコンが新しくなりました（緑の地に、枝と葉と実）。

### マニュアル

- 「設定 → その他」の「マニュアルを開く」で、0.9 の画面に合わせた新しいマニュアルがブラウザで開きます。
- Edge や Chrome で印刷すると、表紙・目次・ページ番号の付いた A4 の形になり、PDF にもできます。
- 「だれが何をするか」の節に、メンバー・リーダー・組織の持ち主（先生など）のすることをまとめました（印刷すると新しいページから始まるので、その部分を配れます）。

## 変わったこと・注意

### 更新のしかた

- 0.3.x をお使いの方は、アプリの上に「新しいバージョン 0.9.0 が利用可能です」と出たら「今すぐ更新」を押してください。出ないときは、Releases のページ（https://github.com/y0zrin/LifeManager/releases）からインストーラーを入れて上書きしてください。
- Issue・マイルストーン・ラベル・設定・日誌は GitHub にあるので、更新してもそのまま使えます。この PC のトークンとプロジェクトの一覧も引き継ぎます。
- 画面の切り替えは、上のボタンからサイドバーに移りました。プロジェクトの切り替えも、サイドバーのプルダウンで行います。
- git の作業を始めるときは、「作業」タブか、左上のリポジトリの「⋯」で、作業フォルダを決めます。

### トークンと組織での許可

- Actions・チェック・セキュリティのお知らせには、「Actions」（Read and write）・「Checks」「Commit statuses」「Dependabot alerts」「Code scanning alerts」（Read-only）の権限もいります。
- プルリクを使うには、GitHub の Life Manager App に「Pull requests」の権限がいります。持ち主（組織なら組織の持ち主）が、GitHub の Installed GitHub Apps で権限の更新を承認してください。自分で作ったトークンで入っているときは、トークンに「Pull requests」の権限（Read and write）を足します。

- リーダーがメンバーのトークンを作って配るやり方は、やめてください。メンバーはそれぞれ自分のアカウントで入り、リーダーはリポジトリに招待します。
- 「トークンで入る」の「GitHub で作る」で、名前・期限・権限の入ったトークンの作成ページが開き、貼るとその場で使えるかを確かめます。
- 「設定 → トークン」の「GitHub トークン」で、だれのトークンか・期限・使えるかをプロジェクトごとに見られ、期限が 7 日以内になると画面の上で知らせます。
- 共用の PC で使い終わったら、「設定 → トークン」の「ログアウト」で、その PC からトークンをすべて消せます。GitHub での許可も取り消すときの案内が、ログアウトのあとの画面に出ます。
- 組織（Organization）のリポジトリは、「GitHub でログイン」なら組織の持ち主が Life Manager を組織に一度入れて、使うリポジトリを選べば使えます。トークンで入るときは、トークン 1 本ごとに持ち主の承認がいることがあります。

### データの扱い

- アプリは GitHub の Issue を消しません。サブイシューや関連を外しても、Issue は残ります。
- すでに記録しているファイルを「管理から外して無視する」と、次のコミットで GitHub からも消え、ほかの人がプルするとその人の手元からも消えます（自分の PC のファイルは残ります）。

### 直した不具合

- ルーチンなどの設定を保存した直後に、前の内容が戻ったり、保存が断られたりすることがありました（#64）。
- 日本語の変換を確定する Enter で書きかけのまま送られたり、変換を取り消す Esc で編集が消えたり画面が閉じたりすることがありました（#6）。
- 最初に入れたトークンが、入れ替えたあとも使われ続けることがありました。ルーチン・通知・日誌の自動の処理も、今のトークンで動くようにしました。
- 貼ったトークンに全角文字などが混じると、アプリが落ちることがありました。
- 日誌の書きかけのノートが、消えることがありました。
- カードの本文の抜き出しに、ガントの日程などの見えない印が出ていました。
- ウィンドウの題名に、版が出ていませんでした。

## 既知の制限

- トークンで入っているときは、招待を送る・送った招待を見る・自分用のリポジトリを作るのに、トークンの「Administration」の権限がいります（足りないときは、直し方が出ます）。
- Fine-grained のトークンで入っているときは、届いた招待をアプリの中で受けられません（GitHub の決まりで、そのトークンでは招待を受ける操作ができません）。メールの「View invitation」か GitHub の通知から参加してください。「GitHub でログイン」なら、アプリの中で受けられます。
- 組織への招待は、アプリの中では受けられません。「GitHub で参加」から、GitHub の画面で参加します。
- サブイシューと変更の履歴は、GitHub につながっているときに使えます。ラベルとマイルストーンの作成・変更も、つながっているときに行ってください。
- 子の Issue をすべて閉じても、親は自動では閉じません。ガントには、親子の帯は出ません。
- Actions の山は、最近の 100 回の実行から作ります。
- アクティビティの「チームの動き」は、GitHub が残している最近の 90 日ほど（100 件まで）です。リリースを消すのは GitHub の画面で行います。

## 開発者向け

- git の操作は、PC の git を Rust から呼び出します（`life-manager/src-tauri/src/git`）。送信待ちとまとめは `life-manager/src-tauri/src/offline` にあります。
