# 実機での確認項目（オフライン対応・v0.9 リポジトリ管理）

ブラウザの確認用ページ（偽のバックエンド）と Rust の単体テストでは確かめてあるが、本物のアプリではまだ動かしていないもの。
★ は先に確かめたいもの。

## 準備

- 捨ててよいテスト用のリポジトリを用意し、GitHub の Web 画面で同じ Issue・設定ファイルを直せるようにしておく
- 回線は Wi-Fi を切って（または機内モードで）止める。「オフライン」の表示は、次の通信に失敗したときに出る
- 起動は `npm --prefix life-manager run tauri dev`

## A. 読み込み（手元の写し）

- [ ] A1 ★ オンラインで起動し、各画面を一度開く → 回線を切って更新 → Issue・ラベル・マイルストーン・担当者が出る。上に「オフライン」
- [ ] A2 回線を切ったまま起動し直す → 最後に読んだ内容が出る
- [ ] A3 一度開いた Issue のコメントがオフラインでも見える（開いたことのない Issue は、送信待ちのコメントだけ）
- [ ] A4 ルーチン・通知・リマインダー・ボードの設定と、一度開いた日の日誌が、オフラインでも出る

## B. Issue の変更（送信待ち）

- [ ] B1 ★ オフラインでメモ投入・Issue 作成 → 「仮1」と「未送信」の印。状態の欄に「（未送信…）」
- [ ] B2 ★ オフラインで 完了／再開、ボードのドラッグ、ラベル・担当者・マイルストーン・タイトル・本文の変更、チェックの付け外し、コメント → それぞれ「未送信」。上の「未送信 N」を押すと一覧に並ぶ
- [ ] B3 仮の番号の Issue を閉じる／コメントする／ガントの日程と先行タスクを付ける／リマインダーを付ける
- [ ] B4 ★ 回線を戻す → 30 秒以内（または「今すぐ送る」）で送られ、「仮1」が本当の番号に変わる。開いていた詳細も新しい番号に切り替わる
- [ ] B5 送れたあと、Discord の通知が本当の番号とリンクで届く（送信待ちのあいだは届かない）
- [ ] B6 仮の番号を参照していた本文・先行タスク・リマインダーが、本当の番号に直っている（GitHub の Web で確認）
- [ ] B7 送信待ちを残してアプリを終了 → 起動し直しても残っていて、つながると送られる

## C. GitHub 側の変更とのまとめ・競合

- [ ] C1 ★ オフラインでタイトルを変え、そのあいだに Web で同じタイトルを別の内容に → 回線を戻すと「確認 1」。「GitHub の内容を残す」「自分の変更で上書き」「手で直す」をそれぞれ試す
- [ ] C2 ★ 本文: オフラインで 1 行目、Web で 3 行目を変える → 確認なしで両方残る
- [ ] C3 本文: 同じ行を両方で変える → ぶつかった所だけ選ぶ画面。「両方」で送れる。「手で直す」で印を残したまま送ろうとすると止められる
- [ ] C4 オフラインで状態ラベルを変え、Web で優先ラベルを足す → 両方残る
- [ ] C5 オフラインでチェックを付け、Web で項目を足す → 足した項目も残り、チェックも付く
- [ ] C6 オフラインで閉じ、Web でも閉じる → 確認に出ない

## D. 設定・日誌

- [ ] D1 オフラインでルーチン・通知スケジュール・イベント通知・ボードを保存 → 「（未送信…）」。つながったら config/*.yaml に反映
- [ ] D2 オフラインで通知スケジュールを変え、Web でイベント通知の側を変える → 両方残る（同じ notifications.yaml）
- [ ] D3 同じルーチンをオフラインと Web の両方で変える → 「確認」に設定のぶつかり（違う行に色）
- [ ] D4 ★ リマインダーをオフラインで追加（仮の番号の Issue にも）→ その時刻に OS の通知が出る。つながったあと reminders.yaml に本当の番号で入り、二重に通知されない
- [ ] D5 オンラインで開いた日の日誌を、オフラインでノート編集・保存 → つながったら journal/日付.md に反映。書きかけのノートが勝手に消えない
- [ ] D6 日誌の作成をオフラインで押す → 「つながったら作ります」。つながると作られる

## E. スケジューラ（アプリを開いたまま）

- [ ] E1 ルーチンの時刻をオフラインで迎える → 仮の番号で Issue ができ、OS の通知。つながったら 1 件だけ作られる
- [ ] E2 ルーチンの自動クローズの時刻をオフラインで迎える → 送信待ちの「閉じる」になる
- [ ] E3 通知スケジュール（今日のタスクなど）の時刻をオフラインで迎える → 手元の写しから OS の通知
- [ ] E4 23:59 の日誌の自動作成をオフラインで迎える → つながってから作られる

## F. 送れないとき

- [ ] F1 送信待ちを残してトークンを無効にする → 「送れませんでした: HTTP 401 …」と出て、送信待ちは残る。トークンを直すと送られる
- [ ] F2 オフラインで変えた Issue を、Web で削除・移動する → 「送れなかった変更」→「分かった」で片付く
- [ ] F3 作成が拒否される（422 など）→ 作成と、その Issue への後の変更が「送れなかった変更」に並ぶ
