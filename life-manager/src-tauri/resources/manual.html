Life Manager マニュアル

タスク管理と、git によるバージョン管理を、画面で見ながら行うためのアプリです。

このマニュアルは、左のサイドバーから「作業」「ブランチ」「全体図」を使える版（0.9 以降）に合わせています。サイドバーは、ホーム（オーバービュー・ヒストリー）・タスク（作業から）・リポジトリ の 3 つに分かれています。

マニュアルは 6 つの部（はじめる・ホーム・タスクを管理する・git で作業する・GitHub でチームと作る・設定と困ったとき）に分かれ、章と節に番号が付いています。左の目次は、読んでいる章だけ節まで開きます。上の欄で、章・節の名前から探せます。

第 1 部はじめる

はじめに

Life Manager は、GitHub のリポジトリを使って、次の 2 つをまとめて行うアプリです。

  • タスク管理: やること（Issue）を作り、状態や期限、目標（マイルストーン）で整理します。
  • バージョン管理: ファイルの変更を git で記録し、GitHub に送ります。どの操作でも、実際に実行される git のコマンドが画面に表示されるので、使いながら git を覚えられます。

データはすべて GitHub のリポジトリに保存されます（Issue・マイルストーン・ラベル・設定ファイル）。アプリを消しても、データは GitHub に残ります。

学ぶためのしかけ

「作業」タブでは、今どの段階にいるのか（Issue を選ぶ → ブランチ → 変更 → コミット → プッシュ → 完了）と、次に何をすればよいかを案内します。ステージやコミットなどの意味の解説も表示されます（設定 → 表示 で消すこともできます）。

インストールと更新

  1. 配布されたインストーラー（Life Manager_x.x.x_x64-setup.exe）を実行します。
  2. 画面の案内に沿ってインストールします。
  3. 最後に、Git が入っているかを調べます。入っていなければ「今すぐ Git をインストールしますか？」と聞かれます。はい を押すと、Git を自動でインストールします（数分かかります）。
  4. 終わったら、スタートメニューかデスクトップから Life Manager を起動します。
「このアプリがデバイスに変更を加えることを許可しますか？」と出たら

Git のインストールには、PC の管理者の確認が必要です。はい を押してください。学校や会社の PC で管理者の確認ができないときは、PC の管理者に Git のインストールを頼んでください。

インストールのときに いいえ を選んだ場合や、うまく入らなかった場合も、アプリを起動したときにもう一度案内が出ます（「使う準備」）。

新しいバージョンが出ると、アプリの上に「新しいバージョン … が利用可能です」と表示されます。今すぐ更新 で更新できます。後で で閉じても、設定 → その他 の「バージョン」から更新できます。起動したときのほか、そこの 新しいバージョンを確かめる でも確かめられます。

初期セットアップ

はじめて起動すると、セットアップの画面が出ます。3 つのステップで終わります。トークンを自分で作る必要はありません。

はじめに: 見た目を選ぶ

はじめて起動すると、まず見た目（テーマ）を選ぶ画面が出ます。まん中のカードに、そのテーマのミニの画面（ボードと机。付箋が運ばれ、後ろの粒が動く）が出て、画面ぜんたいもそのテーマになります。← →（マウスでも）で選び、このテーマではじめる（Enter）でログインへ進みます。あとから 設定 → 表示 で、いつでも変えられます（セットアップのあいだは、上の手順の「1. 見た目」を押すと選び直せます）。

ステップ 1: GitHub にログイン

起動すると、まず GitHub へのログインです。「アカウントを持っている」と「持っていない」の 2 つが並びます。

  1. 持っている: この PC で使う期限（30 日・90 日・半年）を選んで GitHub でログイン を押すと、アプリに 8 文字のコード（例 WDJB-MJHT）が出て、コピーされた状態でブラウザに GitHub が開きます。
  2. ブラウザで貼り付け（Ctrl+V）、Continue → Authorize を押します（GitHub にログインしていなければ、先にログインします）。
  3. アプリに戻ると「○○ としてログインしています」と出て、次に進みます。

アカウントを持っていないとき

「持っていない」の欄に、用意するものが出ています。先に用意しておくと、登録の途中で止まりません。

用意するもの決まり
メールアドレス今すぐ受け取れるもの。登録の途中で、数字のコードが届きます
パスワード15 文字以上か、8 文字以上で数字と英小文字を入れる
ユーザー名英数字とハイフン。チームに伝える名前で、公開されます（あとで変えられます）
  1. GitHub で作る を押すと、ブラウザで GitHub の登録のページが開きます。
  2. メール・パスワード・ユーザー名を入れて Continue。人の確認（パズル）をして、メールに届いたコードを入れると登録できます。使い方などの質問が出たら、飛ばして（Skip）かまいません。
  3. アプリに戻って 作れた・ログインへ を押します。コードをコピーしてログインのページを開くので、貼って Continue → Authorize を押すだけです（登録したばかりなので、GitHub にはもう入っています）。
ログインで許可すること

Life Manager が、あなたの代わりに、Life Manager を入れたリポジトリ（持ち主が選んだもの）だけの Issue・プルリクとファイル（設定・日誌）を読み書きできるようになります。パスワードはアプリに渡りません。

鍵は 8 時間ごとに自動で新しくなり、選んだ期限が来ると、もう一度ログインします（半年使わないと、GitHub 側でも切れます）。GitHub の側の変更（アプリの権限を足したときなど）で、鍵が期限の前に使えなくなったときも、自動で新しくして続けます。今の鍵がいつまでか・前に新しくしたときの結果は、設定 → トークン の「🔑 今の鍵は…」に出ます（新しくできなかったときは、わけが黄色で出ます）。今すぐ新しくしてみる で、8 時間を待たずに、鍵を新しくできるかを確かめられます（できなくても、今の鍵は期限まで使えます）。やめたいときは、GitHub の Settings → Applications → Authorized GitHub Apps から Life Manager App を取り消せます（GitHub の画面では、この名前で出ます）。

ステップ 2: 使い方を選ぶ

ログインすると「どのように使いますか？」と出るので、3 つから選びます。招待が届いていれば、招待を受ける に「N 件届いています」と印が付きます。次の画面には、選んだものだけが出ます。選び直すときは ← 戻る。

選ぶものだれが次の画面ですること
チームを作るリーダーリポジトリを用意して、メンバーを招待します
招待を受けるメンバー自分の GitHub の名前をリーダーに伝えて、届いた招待で参加します
個人で使う1 人で使う人自分だけのリポジトリを用意します（あとからチームにもできます）

ステップ 3: チームを作る・個人で使う

先に もうあるリポジトリを使う か 新しく作る かを選びます。

  • もうあるリポジトリを使う: ① 使用するリポジトリを選ぶ を押すと、GitHub の Life Manager App の画面が、あなたのアカウントを選んだ状態で開きます。使うリポジトリだけを選んで Install を押すと、アプリが自分で気づきます（2 つ目からは リポジトリを追加する → GitHub で足して Save）。② 許可したリポジトリを選んで、下のボタンを押します。
  • 新しく作る: 3 つの手順で進めます（「リポジトリを追加する」の「新しく作る」と同じ）。① 作る → ② Life Manager に許可（作ったリポジトリだけ）→ ③ この PC に（クローン）。

最後のボタンは、チームを作るときは はじめて、メンバーを招待する（はじまると 設定 → 接続 が開くので、メンバーを招待します。「チームで使う」）、個人で使うときは はじめる（タスクの画面になります）です。

ステップ 3: 招待を受ける

あなたの GitHub の名前が大きく出ます。この名前をリーダーに伝えます（コピー でコピーもできます）。リーダーが招待すると、GitHub からメールが届くので、View invitation → Accept invitation を押します（リーダーから届いたリンク https://github.com/持ち主/名前/invitations を開いても同じです）。参加すると、アプリが自分で気づいて「○○ に参加しました」と出るので、このリポジトリではじめる を押します。

招待は、アプリの中には出ません（「GitHub でログイン」では、参加する前のリポジトリはアプリから見えないという GitHub の決まりのため）。前から参加しているリポジトリは「ほかに参加しているリポジトリ」から はじめる で選べます。

参加したのに「まだ使えません」と出る

チームのリポジトリは、持ち主（リーダー。組織のリポジトリなら組織の持ち主）が一度だけ Life Manager を入れて、そのリポジトリを選ぶと使えるようになります。リーダーに送る文をコピー で頼んでから、もう一度確かめる を押してください（「チームで使う」）。

はじめたあと、PC では続けて、git を使う準備（Git のインストール・コミットに使う名前）の案内が出ます。

ヒント

接続したら、設定 → タスク の ラベル一括作成 を一度押しておくと、Life Manager で使うラベル（種別・分野・状態・優先）がリポジトリに作られます。

トークンで入る（学校で指定されたときなど）

ログインの画面の下の トークンで入る から、自分で作ったトークン（Fine-grained token）でも使えます。組織のリポジトリでは、トークン 1 本ごとに組織の持ち主の承認がいることがあります。届いた招待は、アプリの中では受けられません（メールから受けます。「だれが何をするか」）。

  1. GitHub で作る を押すと、名前・期限（90 日）・権限が入った状態で、GitHub のトークンの作成ページが開きます。
  2. Repository access で Only select repositories を選び、使うリポジトリを選びます（ここだけは自分で選びます）。組織のリポジトリなら、Resource owner を組織にします。
  3. Generate token を押し、出てきたトークン（github_pat_ で始まる文字列）をコピーして、アプリに貼ります。貼るとすぐ、だれのトークンか・期限・リポジトリが見えるかを確かめ、足りないときは直し方が出ます。

画面の動き

画面は、動いた向きに合わせて動きます（設定 → 表示 の「画面の動き」で少なめにもできます）。画面ごとに色があり、サイドバーの印と上の題の線がその色になります（タスクは青、ボードは緑、マイルストーンは紫 など）。

動きどんなとき
上下縦のサイドバー（左・右に置いたとき）で画面を移る。下の画面へは下から、上へは上から入れ替わります。左に一覧・右に詳細のときに、上下のタスクを選ぶ。タスクの並び・まとめ方を変えると、カードが新しい場所まで動きます
左右横の帯（上・下に置いたとき、スマホの下のナビ）で画面を移る。設定の区分や、作業の「変更／退避中」のタブを移る。右へは右から、左へは左から入れ替わります
奥行き作業 → ブランチ → 全体図 は一歩ずつ引き、戻ると寄ります。一覧のカード（表の行）を押すと、カードがふくらんで詳細になり、閉じると元の場所へ戻ります

サイドバーの印は、次の画面の印まですべって移ります。カードは画面に入るときに順に出ます。メモなどで新しく入ったカード（表なら行）は、上から入ってキラキラし、少し光ります（表の行には「NEW」が付きます）。

完了のお祝い

Issue を完了にすると（カードの 完了、詳細の 完了として閉じる、作業の流れの #N を完了にする、まとめて完了）、押したところからキラキラが散ってスタンプが押され、下のまんなかに「✨ #45 を完了しました」と出ます。スタンプは毎回かわります（はんこ「済・完了・OK」、先生のはんこ「たいへんよくできました」など、英語のバッジ「Great job!」など、絵文字「💯 🎉 🏆」など）。知らせのことば（おつかれさま！・Nice! など）も毎回かわります。まとめて完了したときは「3 件を完了しました」と 1 回だけ出ます。予定なし・重複として閉じたときは出しません。「画面の動き: 少なめ」では、知らせだけ出ます。

サイドバーの一番下には、ログインしている GitHub のアカウント（アイコン・名前・期限）が出ます。押すとメニューが開き、どの方法でログインしているかと期限を確かめたり、アカウントを切り替える、名前をコピー（チームのリーダーに伝えるとき）、GitHub のページを開く、ログインとトークン…（設定 → トークン）、ログアウト（その場で確かめてから）ができます。期限が 7 日を切ると、期限の文字が黄色になります。サイドバーを上・下に置いたときは、帯の右端にアイコンだけが出ます。

リポジトリを選ぶ

左上のリポジトリ（📦）を押すと、画面いっぱいにリポジトリを選ぶ画面が出ます。まん中に大きく、左右にとなりのリポジトリが並びます。← →（マウスでも）で選んで、Enter か 開く で切り替わります。Esc で閉じます。

  • カードには、開いている Issue・レビュー待ちのプルリク・最後の更新・公開か非公開か・チームの人数（顔）と、この PC のフォルダが出ます。
  • この PC にまだないリポジトリは、開くときに「クローンして開きますか？」と聞きます。⬇ クローンして開く… で置き場所を選ぶと、クローンしてから開きます。クローンせずに開く を選ぶと、次からは聞きません（タスクだけ使うとき）。
  • カードの ⋯ で、この PC のフォルダを選ぶ・変える・クローンする・設定を外す、エクスプローラーで表示、GitHub で開く、一覧から外す ができます。
  • 下の帯に、使うリポジトリの一覧と ＋ リポジトリを追加…（「使う準備」）が出ます。
  • 右上の自分を押すと、アカウントを選ぶ画面に移ります。
  • スマホでは、左上のリポジトリを押すと一覧が開きます。

アカウントを切り替える

1 台の PC で、いくつかの GitHub のアカウントを使い分けられます（先生のアカウントと練習用のアカウント、共用の PC など）。メニューの期限のすぐ下の ⇄ アカウントを切り替える を押すと、画面いっぱいにアカウントを選ぶ画面（大きな丸が横に並びます）が出ます。この PC にアカウントが 2 つ以上あると、起動したときにもこの画面が出ます。

  • ← →（マウスでも）で選んで Enter で、ログインし直さずに切り替わります。今のアカウントはログアウトしないので、いつでもこの画面から戻れます。起動したときは、今のアカウントのまま Enter（か Esc）で、そのまま始まります。
  • アカウントごとに、使うリポジトリの一覧と、最後に開いていたリポジトリを覚えます（切り替えると、左上のリポジトリの一覧も変わります）。この PC のフォルダ（作業フォルダ）と表示の設定は、アカウントをまたいで同じです。
  • いちばん右の ＋ アカウントを追加 で、今のアカウントのまま、もう 1 つログインします。先に、ブラウザの GitHub を、追加したいアカウントに切り替えてください（GitHub の右上のアイコン →「Switch account」か「Add account」）。今のアカウントのままだと、同じアカウントが入ります。やめるときは、上の やめる（…に戻る） で前のアカウントに戻ります。
  • 選んでいるアカウントの 〇〇 をこの PC から外す…（右下）で、そのアカウントを この PC から外せます（そのアカウントのログアウト）。使うリポジトリの一覧は残るので、もう一度ログインすれば続きから使えます。
  • ログアウト は、今のアカウントだけです。ほかのアカウントが残っていれば、そちらに切り替わります。
  • まだ GitHub に送っていない変更（送信待ち）があるあいだは、切り替えられません。送ってから切り替えます。
  • ルーチンの作成やリマインダーなど、自動で動くものは、今のアカウントのリポジトリだけで動きます。

サイドバーの ◀ たたむ（Ctrl＋B）を押すと、サイドバーを隠して画面を広く使えます。隠したあとは、ウィンドウの端（サイドバーのあった側）にマウスを寄せると出てきて、離れると引っ込みます。出てきたサイドバーの 📌 固定する（Ctrl＋B）で、元のように出しっぱなしに戻ります。

「作業」「ブランチ」「全体図」は、左から右へ一歩ずつ引いて見る関係になっています。− キーで一段引き、＋ キーで一段寄れます（Ctrl ＋ マウスホイールでも同じです）。

使う準備（Git・名前・作業フォルダ）

「作業」「ブランチ」「全体図」で git を使うための準備です（PC のみ）。

Git のインストール

アプリを起動したとき、Git が入っていなければ「Git をインストールしますか？」と表示されます。インストールする を押すと、Git を入れます。

# Windows で実行されるコマンド（Windows に入っている winget を使います） winget install --id Git.Git -e --source winget

winget が使えない PC では、Git for Windows の公式のインストーラーを GitHub から取ってきて実行します。Mac では、Git が入った「コマンドライン ツール」のインストール画面が出ます。

あとでインストールする場合は、設定 → その他 の「この PC の git」にある Git をインストールする… からも入れられます。起動のたびに案内が出てほしくないときは、案内の画面で「次からは起動時に表示しない」にチェックを入れます。

コミットに使う名前とメールアドレス

コミットには、だれが変更したかを残すため、名前とメールアドレスを付けます。決まっていないと、案内の画面で入力を求められます。はじめから、GitHub のアカウントの名前と、GitHub が用意する公開用のアドレス（…@users.noreply.github.com）が入っています。

git config --global user.name "名前" git config --global user.email 12345+ユーザー名@users.noreply.github.com
なぜ noreply のアドレス？

コミットに付けたメールアドレスは、GitHub で公開されます。GitHub が用意する noreply のアドレスを使うと、ふだんのメールアドレスを知られずに、コミットを自分のアカウントに結びつけられます。

今の設定は、設定 → その他 の「この PC の git」の 使う準備を確かめる で見られます（変更もできます）。

作業フォルダを決める

作業フォルダは、リポジトリのファイルを置く、この PC 上のフォルダです。左上のリポジトリを押して出る一覧で、そのリポジトリの ⋯ から決めます（作業タブを開いたときの準備の画面からも決められます）。

「⋯」の中使うときすること
この PC にクローンする…まだ PC にリポジトリがないとき選んだフォルダの中に、リポジトリと同じ名前のフォルダを作ってコピーします（git clone）。
この PC のフォルダを選ぶ…（変える…）すでにクローンしてあるときそのフォルダが、そのリポジトリのものかを確かめてから使います。中のフォルダを選んでも、リポジトリのいちばん上のフォルダになります。
エクスプローラーで表示フォルダの中を見たいときエクスプローラー（Mac は Finder）で、そのフォルダを開きます。
フォルダの設定を外す別のフォルダにしたいとき設定だけを外します。フォルダやファイルは消えません。
# クローンのときに実行されるコマンドの例 git clone https://github.com/オーナー名/リポジトリ名.git D:\work\リポジトリ名

作業フォルダは PC ごと・リポジトリごとに覚えます。左上のリポジトリの一覧では、フォルダが決まっているリポジトリに 📁 とフォルダの場所が出ます。

作業フォルダがない PC やスマホでも、「ブランチ」「全体図」は GitHub にある状態を表示でき、コミットの 変更内容を見る も使えます（見るだけで、操作はできません）。

リポジトリを追加する

左上のリポジトリを押し、一覧の一番下の ＋ リポジトリを追加… を押すと、どこにあるリポジトリかを選ぶ画面になります（設定 → 接続 の ＋ リポジトリを追加… からも開けます）。追加すると、そのリポジトリに切り替わります。

選ぶものすること
GitHub にある（リモート）使えるリポジトリの一覧から選ぶか、URL（https://github.com/持ち主/名前、git@github.com:持ち主/名前.git、持ち主/名前 のどれでも）を貼ります。この PC にも持ってくる（クローン） にチェックを入れると、置き場所を選んでクローンし、そのフォルダを作業フォルダにします。一覧にないときは リポジトリを追加する（GitHub で Life Manager に選ばせる）で出てきます。
この PC にある（ローカル）フォルダを選びます。GitHub からクローンしたフォルダなら、そのまま追加して作業フォルダにします。GitHub にまだないフォルダは、GitHub に上げる… で上げてから追加します（下の「手元のフォルダを GitHub に上げる」）。
新しく作る下の 3 つの手順で、GitHub に自分のリポジトリを作ります。

新しく作る（作る → Life Manager に許可 → この PC に）

  1. 作る: 名前を決めます（はじめは非公開）。まだ自分のアカウントに Life Manager を入れていないときは、GitHub で作る でブラウザが開くので、「Add a README file」にチェックを入れて「Create repository」を押し、戻って 作ったので次へ を押します。もう入れてあるとき（とトークンで入ったとき）は、作る でアプリが作ります。
  2. Life Manager に許可: 許可する画面を開く で GitHub が開きます。「Only select repositories」→ 作ったリポジトリを選んで Install（2 回目からは足して Save）を押すと、アプリが自分で気づいて次へ進みます。作ったリポジトリだけを許可するので、ほかのリポジトリには触れません。アプリで作ったときは、自動で許可に入るので、この手順は飛ばします。
  3. この PC に: この PC にも持ってくる（クローン） で置き場所を選び、クローンして追加する。git の作業をしないなら、チェックを外して 追加する。

一覧の各行の ⋯ では、この PC のフォルダ（上の表）のほかに、GitHub で開く、一覧から外す（GitHub のリポジトリやフォルダは消えません）ができます。今使っているリポジトリは、ほかに切り替えてから外します。

手元のフォルダを GitHub に上げる

まだ GitHub に無いフォルダ（課題や作品のフォルダ）は、リポジトリを追加 → この PC にある（ローカル） でフォルダを選び、GitHub に上げる… から、4 つの手順（「GitHub でログイン」のときは 5 つ）で上げられます。

  1. 記録を始める: 上げるフォルダを選びます。まだ Git の記録がなければ、記録を始め（git init）、.gitignore のひな形（Visual Studio / Unity / Unreal Engine）を置いて、今の中身を最初のコミットにします。
  2. GitHub に場所を作る: GitHub で作る でブラウザが開きます。README や .gitignore は付けずに「Create repository」を押し、戻って 作ったので次へ を押します（リポジトリができたかを確かめます）。
  3. つないで送る: GitHub の置き場所を origin という名前で登録し、送ります（git push -u）。
  4. Life Manager に許可（「GitHub でログイン」のとき）: 上げたリポジトリだけを Life Manager に許可します（上の「新しく作る」の ② と同じ）。しないと、Issue やタスクが使えません。
  5. できあがり: プロジェクトに登録し、このフォルダを作業フォルダにします。
# 実行されるコマンドの例 git init -b main git add . git commit -m "最初のコミット" git remote add origin https://github.com/持ち主/名前.git git push -u origin main

ほかのリポジトリの中にあるフォルダは上げられません。GitHub は 100MB を超えるファイルを受け付けないので、そういうファイルがあるときは、コミットする前に知らせます（記録しないなら .gitignore に書き、記録するなら Git LFS を使います）。

プッシュ（コミットの一覧つき。押すと変更内容）・プルリクを作った・マージした・承認した・Issue を作った・完了にした・コメントした・担当にした・ブランチやタグ・リリースなどが、日ごとに新しい順で出ます。だれ と 種類（Issue・プルリク・プッシュ・リリース・そのほか）で絞れます。日ごとの件数と、絞り込んだ全部の件数も出ます（だれ・種類 の選択肢には、選ぶと何件になるかが出ます）。GitHub が残している、最近の 90 日ほど（100 件まで）です。

おしらせと「助けを求める」

「あなたがすること」に新しく出てきたもの（担当になった・レビューを頼まれた・名前を呼ばれた・修正を頼まれた・承認された・期限が近い・チェックや Actions の失敗）と、🆘 助けを求められた・マイルストーンの達成を、おしらせとして知らせます。アプリは 2 分ごと（ヒストリーを開いているあいだは 1 分ごと）に GitHub を見に行きます（PC のみ）。

画面の角に出る知らせ

  • 知らせは、アプリの窓の外の、画面の角の小さな窓に出ます（ほかのアプリを使っていても見えます）。出す角は 設定 → 通知 の「アプリのおしらせ」で、右上（はじめはこれ）・右下・左上・左下・アプリの中だけ から選べます。🔔 ためしに出す で、どこに出るかを確かめられます。
  • × か 開く を押すまで残ります。3 つまで重ね、ほかは「ほか N 件」（押すと、りれきが開きます）。開く で Life Manager が前に出て、その Issue・プルリク・Actions を開きます。
  • 🆘 は赤く目立って出ます。
  • 起動したときに、前に閉じてからたまっていたものは、1 つにまとめて知らせます（🆘 は、まとめずに 1 つずつ）。

× を押しても、インジケーターに残る

Life Manager の窓の × を押しても、アプリは終わらず、画面の右下のインジケーター（タスクトレイ。^ の中に隠れていることがあります）に残り、おしらせを出し続けます。インジケーターのアイコンを押すと、窓が戻ります。終えるときは、アイコンを右クリック → 終了する。× で終えたいときは、設定 → 通知 の「× を押したとき」を 終了する にします。はじめて × で残したときは、そのことを知らせます。

Life Manager をもう 1 つ起動しようとしたときは、すでに動いている Life Manager の窓が前に出ます。

🔔 おしらせ（りれき）

上のバーの 🔔 で、届いた知らせのりれきが右から出ます。日ごと（今日・昨日・おととい …）に、60 日まで残します（この PC に。リポジトリごと）。🆘 助けて・自分の番・レビュー・失敗・達成 で絞れます。押すと、そのときの詳しい中身（助けてのメッセージ・いっしょに送られたもの・コメントの文）と 開く › が出ます。

未読の数は出しません（片付ける受信箱にはしません）。新しい知らせが来たときだけ 🔔 に小さな赤い点が付き、りれきを開くと消えます。

🆘 助けを求める

困ったら、Issue の詳細の見出しの 🆘 助けを求める（作業タブでは上のバーにも）を押します。

  1. だれに: チームの人を選びます（2 人のチームなら、はじめから選ばれています）。
  2. 困っていること: 何をしたら、どうなったかを書きます（Ctrl+Enter で送れます）。
  3. いっしょに送るもの: 今のブランチと作業中の変更の数・最後に失敗した git のコマンドとメッセージ（この 30 分のもの）・競合しているファイル。送りたくないものは外せます。
  4. 🆘 送る で、その Issue に、選んだ人を @ で呼ぶコメントとして残ります（GitHub にも残り、あとから読めます）。

呼ばれた人のアプリには、赤い 🆘 の知らせが出ます。Issue の履歴では、🆘 のコメントが赤い枠で、呼んだ人・困っていること・今のようす に整えて出ます。💬 返事を書く で、コメントの欄に @ を入れて書けます。解決したら ✅ 解決した を押すと「解決しました」のコメントが残り、助けを求めた人と呼ばれた人に ✅ の知らせが届きます。

第 3 部タスクを管理する

タスク一覧

タスク（Issue）を一覧にして、探す・絞り込む・まとめて直す画面です。ふだんのタスクの流れは、マイルストーンを作る → ボードでタスクを足す → 日程・見積もりを入れてガントで見る、です（サイドバーもこの順です）。

クイックメモ

画面の角の 📝 を押すか、Ctrl＋M で小さな欄が開きます（どの画面からでも使えます）。文字を入れて Enter で投入し、そのまま続けて書けます。Esc か、欄の外を押すと閉じます（書きかけは残ります）。メモは、今のリポジトリの Issue（種別:メモ・状態:未整理）として登録され、タスクの一覧に出ます。

  • 分野は、そのリポジトリの「分野:」のラベルから選びます（前に選んだものを覚えます。「なし」も選べます）。
  • 📝 を置く角は、設定 → 表示 の「メモのボタン」で 右上・右下・左上・左下・隠す から選べます（はじめは左下）。サイドバーや上のバーにはかぶらない所に出て、たたんだサイドバーが端から出てきたときは、押し出されて動きます。「隠す」にすると、ボタンは出さず、Ctrl＋M で画面の上のほうに欄が開きます。マウスを乗せると大きくなります。
  • ほかの欄で文字を打っているあいだは、じゃまにならないよう画面の外へよけ、打つのをやめると戻ってきます。☑ 選ぶ の帯が出ているあいだも、よけます。
  • Issue の詳細やダイアログを重ねて開いているあいだは、Ctrl＋M は効きません（閉じてから使います）。

テンプレート

フォームのいちばん上で テンプレート を選ぶと、題名の頭・本文・ラベルが入ります（あとから直せます）。本文に自分で書いた内容があるときは、本文は入れ替えません。

  • テンプレートは GitHub と同じもので、リポジトリの .github/ISSUE_TEMPLATE/ に置いた Markdown ファイルです。GitHub の「New issue」でも同じものが出ます。
  • まだテンプレートがないリポジトリでは、見本の 3 つ（🐞 バグ報告・✅ やること・🔍 調べもの）が使えます。このリポジトリに置く を押すと、3 つのファイルを 1 つのコミットにして GitHub のリポジトリに置きます（作業タブでプルすると、手元にも来ます）。
  • 中身を変えるときは、そのファイルを直します（作業タブでコミット、または GitHub で編集）。先頭の --- で囲んだところに、名前（name）・説明（about）・題名の頭（title）・ラベル（labels）を書きます。
# .github/ISSUE_TEMPLATE/bug.md の例 --- name: "🐞 バグ報告" about: "動かない・おかしい" title: "[バグ] " labels: ["種別:バグ", "状態:未整理"] --- ## 何が起きたか

絞り込み

上の行の左端の検索欄で、タイトル・本文・番号で探せます。そのとなりの フィルタ を押すと、種別・分野・状態・優先・見積・担当者・マイルストーン・表示（オープンのみ・クローズのみ・両方）の一覧が開き、押すとすぐに一覧に反映されます。更新 と ＋ イシュー作成 は、同じ行の右端にあります。

  • ラベル（種別・分野など）は複数選べます。2 つ以上選ぶと、どれか（選んだラベルのどれかが付いている）と すべて（選んだラベルがすべて付いている）を切り替えられます。
  • 種類どうし（たとえば「分野」と「状態」）は、両方に当てはまるものだけが出ます。
  • かけている絞り込みは、フィルタ の数と、下の小さなチップで分かります。チップの × で外せ、すべて外す でまとめてやめます。

並び・期限

  • 並び: 新しい順・古い順・更新が新しい順・優先度順（高 → 中・なし → 低）・期限が近い順。次に開いたときも同じ並びです。
  • カードの 📅 10/10（あと 12 日） が期限です。期限は、ガントの終了日、なければマイルストーンの期限です。3 日以内は黄色、過ぎたら赤で ⚠ 9/25（3 日超過） と出ます。

見せ方・まとめ方

  • 左に一覧・右に詳細（PC で窓が広いとき・カードのとき）: 一覧が左に、押したタスクの詳細が右に出ます（重ねて開かないので、閉じる手間がありません）。↑↓ で上下のタスクに移れます（文字を打つ欄にいるときは効きません）。左右の境目をドラッグすると幅を変えられます。選んだタスクと幅は、次に開いたときも同じです。右上の × で右を空にします。窓が狭いとき・スマホ・表のとき、ほかの画面から開くときは、今まで通り詳細を重ねて出します。
  • カード｜表: 表にすると、1 行に 1 件で 番号・題・状態・優先・担当・マイルストーン・期限 が並びます（窓の横いっぱいに広がります）。行を押すと詳細が開きます（☑ 選ぶ のあいだは、押すと選べます）。
  • まとめる: なし・親子・状態・優先・分野・担当・マイルストーン。まとまりごとに見出しと件数が出ます。 親子は、サブイシュー（子）を親のすぐ下に字下げして並べます（「Issue の詳細」）。 状態はボードの列の順に並び、閉じた Issue は「完了」にまとまります。
  • 見せ方とまとめ方も、次に開いたときに同じになります。

保存した見方

絞り込み・並び・まとめ方・カードか表か、をまとめて名前を付けて保存できます。保存した見方 ▾ から選ぶと、その見方に切り替わります。今の設定と同じ見方があるときは、ボタンにその名前が出ます。

  • 保存: 名前を入れて 保存。同じ名前があれば 上書き保存 になります。
  • 名前を変える・消す: 保存した見方を選んでいるときに使えます。
  • マイルストーンの絞り込みも見方に入ります（例: 「0.5.0 の残り」＝マイルストーン 0.5.0・オープンのみ・期限が近い順）。
  • 見方はリポジトリの config/views.yaml に保存され、GitHub に送られます。チームの全員が同じ見方を使えます。担当を「自分」にして保存した見方は、開いた人の担当に読み替わります。
  • 二人が同時に見方を足したときは、両方とも残ります。つながらないあいだの保存は、送信待ちになります（「つながらないとき」）。

詳細の つながり のタブの 🧩 サブイシュー の欄に、子の Issue の一覧と、いくつ終わったか（2 / 5 完了 とバー）が出ます。GitHub の画面でも同じ親子で見えます。

  • 子の ○ を押すとクローズ、題名を押すとその子の詳細が開きます。子の詳細のいちばん上の ↑ 親：#45 … で親に戻れます。

タスク・ボード・マイルストーンのカードには、子のある Issue に 🧩 2/5（子 5 件のうち 2 件が完了）、子の Issue に ↑ #45 親の題名 が出ます。子を全部クローズしても、親は自動では閉じません。サブイシューは、GitHub につながっているときだけ使えます。

クローズ ▾ から、GitHub と同じ 3 つの閉じ方を選べます。閉じた Issue の上には「Closed（完了）」のように、閉じ方が出ます。

成果物（メディアビューワー）

Issue の詳細の 成果物 のタブに、その Issue につながるコミットで変わったファイルが、種類ごとに見本つきで並びます。つながるコミットは、メッセージで「#11」に触れたコミット（作業タブでこの Issue を選んでコミットすると付きます）・Issue にリンクされたコミット・その Issue に触れたプルリクのコミットです。この PC にクローンしてあれば、まだプッシュしていないコミットも探します。画像は縮めて見せ、音は ▶ でその場で鳴らせます。押すとメディアビューワーが開きます。

マイルストーン

期限つきの目標を管理します。Issue をマイルストーンに結びつけると、目標に対する進み具合が見えます。タスクの流れは、ここでマイルストーンを作る → ボードでタスクを足してマイルストーンに入れる → 日程・見積もりを入れてガントで見る、です。

  1. ＋ マイルストーン（クエストでは ＋ ボスを置く）を押します。
  2. 名前（必須）・説明・開始日・期日を入れて、作成 を押します。

ステージセレクト

画面の上半分は、ゲームのステージを選ぶ画面のようになっています。時間の順に並んだ道の上にマイルストーンの印があり、選んでいるマイルストーンが大きなパネルで出ます（左右に、となりのマイルストーンが小さく出ます）。← →、道の印、となりのパネル、‹ › で移ります。開いたときは、今日が期間に入っているマイルストーン（なければ、期限がいちばん近いもの）を選んでいます。道には今日の線も出ます。

  • パネルには、期間と期限までの日数・説明・進み具合のバー・最近のペースとの比べ（目安 21pt に対して 23pt。1 割以上多いと黄色）・かかわった人が出ます。
  • 終えたマイルストーン（閉じた、または Issue が全部閉じた）は、道の印が ★ になり、パネルに CLEAR と星（期限までに全部 ★★★、期限すぎ ★★、残して閉じた ★）が出ます。いちばん先のマイルストーンは GOAL（旗）です。GitHub で閉じたマイルストーンも、Issue が入っていれば道に出ます。
  • 下半分に、そのマイルストーンのタスク（残り → 終わった）が出ます。押すと詳細が開きます。📉 バーンダウン・編集・完了（GitHub のマイルストーンを閉じる。閉じたものは 再開）もここです。
  • ふと見たときに、前に見たときと比べてバーが動きます。前にこの画面で見たときの残りを覚えておき、開いたときに、そこから今の残りまで動きます（減った分が「+3pt」「−6pt」と飛びます）。はじめて見るときは 0 からのびます。見ているあいだにタスクを完了にしたときも動きます。

クエストでは「ボス」

テーマがクエストのときは、マイルストーンがボスになります（STAGE の代わりに BOSS、絵はボス。いちばん先のマイルストーンは城の LAST BOSS）。説明は二つ名、チームはパーティ、終えたタスクは「倒したタスク」です。倒したボス（終えたマイルストーン）には「撃破」の判が押されます。

進み具合のバーは、設定 → 表示 の「マイルストーンの進み具合」で選べます: テーマに合わせる（はじめはこれ。クエストは HP、ほかのテーマは達成率）・達成率（終えた分だけのびる）・HP（残りの量を HP にして、終えた分だけ減る）。HP が減ると、黄色の「減った分」が少し遅れて追いつき、ボスが白く光って揺れます。見積もりを 1 つも付けていないマイルストーンは、件数で数えます。

達成したとき

マイルストーンの最後のタスクを完了にしたとき（どの画面からでも。チームの人が閉じて、読み直したときも）か、タスクを全部終えたマイルストーンの 完了 を押したときに、画面全体が暗くなって大きく祝います。演出は トロフィー・花火・ステージクリア（クエストは「ボス撃破！」）・大きなはんこ（黒板は花丸、ホワイトボードは「達成」、クエストは「撃破」）から毎回ちがうものが出ます。終えたタスクの数・見積もり・期限まで何日残したかと、かかわった人が出ます。

  • 最後のタスクで出たときは マイルストーンを閉じる で、そのまま GitHub のマイルストーンを閉じられます（あとで なら閉じません）。
  • 同じマイルストーンでは 1 回だけです（この PC で覚えています）。どこかを押すか Esc で閉じます。「画面の動き: 少なめ」では、動かさずに出します。

スプリントとして使う（バーンダウン・ベロシティ・サイクルタイム）

マイルストーンを、決まった期間で区切った作業のまとまり（スプリント）として使えます。開始日から期日までがスプリントの期間です。開始日は 編集 で決めます（説明の最後に「開始: 2026-09-28」の形で書かれ、GitHub の画面でも読めます）。決めていなければ、マイルストーンを作った日から数えます。

第 4 部git で作業する（PC）

git のしくみ（まずここから）

git は、ファイルの変更を「いつ・だれが・何を変えたか」として記録する道具です。記録の単位をコミットと呼びます。Life Manager の「作業」タブは、次の流れをそのまま画面にしています。

ブランチは、作業を分けて進めるための「流れ」です。たとえば Issue ごとにブランチを作って作業し、終わったら元のブランチにマージ（合流）します。こうすると、途中の作業がほかの作業と混ざりません。

作業タブ

取り組む Issue を決めて、ファイルの変更をコミットし、GitHub に送るまでを進める画面です。

作業の流れ（上の 1 行の段）

上の 1 行に、8 つの段（Issue → ブランチ → 変更 → コミット → プッシュ → プルリク → マージ → 完了）が並び、今の段が光ります。下には今の段の画面が出て、進むと、次の段の画面に切り替わります。終わった段は ✓ と中身（#45・issue-45・2 ファイル など）になります。段を押すと、その段の画面を見られます（今の段を押すと戻ります）。

  • ① Issue を選ぶ: 未完了の Issue の一覧から選びます（番号やタイトルで探せます。自分の担当が先、その中は進行中が先に並びます）。自分の担当は 始める、自分の担当でない Issue は 自分に割り当てて始める（自分を担当に足します。ほかの担当はそのまま）。始めると状態が「進行中」になり（ボードにも出ます）、次の段の画面に進みます。今の Issue の Issue を開く もここにあります。選んだ Issue は、リポジトリごとにこの PC に覚えておきます。
  • コミットは必ず Issue につなげます: Issue を選んでいないときは、コミットできません（「① Issue を選ぶ」が出ます）。マージを終えるコミットと、直前のコミットの修正（amend）は別です。
  • ③ 変更・④ コミット: 変更のあるファイル・コミット欄・差分の画面です（下の「変更とステージ」「コミット」）。ツールバーの コミット… からも、この画面が開きます。
  • ② ブランチ・⑤ プッシュ・⑥ プルリク・⑦ マージ・⑧ 完了: 次にすることと、そのためのボタンが出ます。
  • ⑥ プルリクの 今回はプルリクしない: いくつかのコミット（いくつかの Issue）をまとめて 1 つのプルリクにするときに押します。今の Issue はすぐに完了になり、このブランチのそのコミットまでは、プルリクの段に進みません（次の Issue は ③ 変更から）。続けてコミット・プッシュすると、またプルリクの段が出て、たまったコミットをまとめてプルリクにできます。
  1. Issue を選ぶ何をするかを決める
  2. ブランチ作業する場所（既定のブランチにいるときは、Issue 用のブランチを作る案内が出ます）
  3. 変更ファイルを編集して、入れたい変更にチェック
  4. コミット要約を書いて記録する
  5. プッシュGitHub に送る
  6. プルリク「このブランチの変更を main に入れて」とお願いする（「プルリク」）
  7. マージレビューしてもらい、main に入れる
  8. 完了Issue を閉じる（Closes #N ならマージで閉じています）。main に戻って最新にする

既定のブランチ（main）で直接コミットしたときは、プルリク・マージの段はとばして、プッシュのあと完了になります。

記録しないファイル（.gitignore）

ビルドの結果・ログ・エンジンが作るキャッシュ・パスワードの入った設定など、記録しないファイルは .gitignore に書いて無視させます。一覧のファイルを右クリックすると、次のメニューが出ます（logs/debug.log を右クリックしたときの例）。

このファイルを無視する/logs/debug.logそのファイルだけ
拡張子 .log のファイルをすべて無視する*.logどのフォルダの .log も
フォルダ logs/ を無視する/logs/そのフォルダの中すべて（すぐ上のフォルダと、いちばん上のフォルダを選べます）
.gitignore を編集….gitignore を直接書き換える（下の説明）

頭の / は「リポジトリのいちばん上から数えた場所」という意味で、その場所だけに当てはまります。書き足したあとは .gitignore 自身が変更として出るので、ほかの変更と一緒にコミットします。

すでに git で管理しているファイル（一度コミットしたファイル）は、.gitignore に書くだけでは無視されません。そのときは確認の画面が出て、管理から外して無視できます（git rm --cached -- ファイル、フォルダなら git rm -r --cached -- フォルダ/）。ファイルは PC に残り、次のコミットで記録から外れます。GitHub からも消えるので、ほかの人がプルすると、その人の手元からも消えます。

.gitignore を編集…（右クリック、または その他 ▾）では、.gitignore を直接書き換えられます。書きまちがえた行を消すときなどに使います。Ctrl＋S で保存します。まだ .gitignore がなければ、保存したときにリポジトリのいちばん上に作ります。

  • 点にマウスを重ねると、コミットの内容がカードで出ます。
  • 点をクリックすると、そのコミットを積み重ねてきたブランチのページで、そのコミットに寄ります（＋ キーで寄ることもできます）。
  • 点・ブランチの名前・ラベルを右クリックすると、操作のメニューが出ます。
  • ☰ ブランチ一覧 から選ぶと、そのブランチの位置まで動きます。

競合（コンフリクト）したとき

プル・マージ・チェリーピック・リバート・リベース・退避した変更を戻す などで、同じファイルの同じところが両方で変わっていると、git は自動でまとめられずに止まります。これが競合です。

競合が起きると、どの画面にいても「⚠ 競合（コンフリクト）が起きました」の知らせが 1 回だけ出ます。競合したファイル・自動でまとまったファイル・直し方・ファイルに入った印の見本が出て、作業タブで直す で作業タブに移ります。競合しているあいだは、サイドバーの「作業」に ⚠ 競合 が出て、作業タブの上に「〇〇の途中です」と出ます。

マージツールで直す

  1. 作業タブの「競合」の欄のファイルを選ぶと、右に 競合を直す が出ます。競合したか所ごとに、左に今のブランチの側（青）、右に取り込む側（紫）が並びます。
  2. か所ごとに ✔ 今のブランチの方を使う か ✔ 取り込む側を使う を押します。使う側は太い枠と「✔ 使う」、捨てる側は薄い打ち消し線と「✖ 捨てる」になります。両方を残すとき（順番も選べます）や、自分で書き直すとき（自分で書く…）は、下のボタンから選びます。選び直すときは やり直す を押します。
  3. すべてのか所を選ぶと 直したので、ステージする が押せます。印を消して、選んだ内容だけをファイルに書き込み、ステージします（git add。「直した」という合図です）。
  4. すべてのファイルを直したら、マージの途中ならコミットすると終わります。リベース・チェリーピック・リバートの途中なら 続ける を押します（git rebase --continue など）。
  • まるごと今のブランチの方に… / まるごと取り込む側に…: ファイル全体を片方の内容にします（git checkout --ours / --theirs）。画像など文字でないファイルは、これで選びます。片方で消されたファイルは、消したままにする… も選べます。
  • エディタで開く: いつものエディタで開いて、自分で直すこともできます。直したら 読み直す を押すか、作業タブでファイルにチェックを入れます。
  • リベースでは、左が「付け替え先（取り込み済みの内容）」、右が「自分のコミット」です。退避した変更を戻したときは、左が「今のファイル」、右が「退避していた変更」です。

ファイルの中では、競合したところに次のような印が入っています（マージツールは、この印を読んで並べています）。

<<<<<<< HEAD 今のブランチの内容 ======= 取り込もうとした内容 >>>>>>> feature

捨てた内容を、あとで入れたいとき

捨てた側の内容も、消えてはいません。取り込もうとしたブランチ（やコミット）に、そのまま残っています。ただし、同じブランチをもう一度マージしても、git は「もう取り込んである」と考えるので、捨てた内容は戻ってきません。あとで要るときは、そのブランチのファイルを見て、手で入れてコミットします（多くの現場でも、このやり方です）。

# feature/udon での menu.txt を見る git show feature/udon:menu.txt # ファイルまるごと feature/udon の内容にする（今の変更は消えるので注意） git restore --source=feature/udon -- menu.txt

マージのコミットをする前なら、マージツールの やり直す で選び直せます。やめたいときは 〇〇を中止… を押すと、始める前の状態に戻ります（git merge --abort など）。

第 5 部GitHub でチームと作る

プルリク

プルリク（プルリクエスト）は、「このブランチの変更を main に入れてください」というお願いです。チームの人が変更を見て（レビュー）、よければ マージ（合流）します。サイドバーの 🔃 プルリク で、左に一覧、右に詳細が出ます。

はじめに 1 回（持ち主・リーダー）

「GitHub でログイン」で使うときは、GitHub の Life Manager に「Pull requests」の権限がいります。持ち主（組織なら組織の持ち主）が、GitHub の Settings → Applications → Installed GitHub Apps → Life Manager App で、権限の更新（Review request）を承認します。承認するまでは、プルリクの画面に「権限がまだありません」と直し方が出ます。自分で作ったトークンで入っているときは、トークンに「Pull requests」の権限（Read and write）を足します（GitHub で作る で作るトークンには、はじめから入っています）。

一覧

レビューする

  • 行にコメント: 変更されたファイルで、行にマウスを乗せると行番号のところに ＋ が出ます。押して書くと、その行へのコメントとして送られます（その場でレビューになります）。
  • 承認する: 変更を見て、よいと判断したことを伝えます（ひとこと添えられます）。
  • 修正を依頼する: 直してほしいことを書いて送ります（書かないと押せません）。直す人は、同じブランチでコミット・プッシュすると、プルリクに足されます。
  • コメントする: 会話にコメントを書きます。

自分で作ったプルリクは、承認・修正の依頼ができません（GitHub の決まり。ほかの人に見てもらいます）。ひとりで作っているときは、差分を自分で確かめてからマージしてかまいません。

マージする

会話のいちばん下のマージの箱に、今マージできるかが出ます。

プルリクを作る

＋ プルリクを作る（作業タブの流れの プルリクを作る… からも）で、次を決めます。

  1. 入れたい変更のあるブランチ → 入れる先: 選ぶと、入るコミットとファイルの数（+42 −2）が出ます。変更を見る ▾ で、作る前に差分を確かめられます。違いがないとき・同じブランチのプルリクがもうあるときは、そう出ます（あるものは 開く で開けます）。
  2. つなげる Issue: 選ぶと、題名に Issue の題名、説明に Closes #45 が入ります。既定のブランチにマージすると、その Issue が自動で閉じます（ブランチの名前が issue-45 のようになっていれば、はじめから選ばれています）。
  3. 題名・説明: 説明には「何を変えたか」「どう確かめたか」のひな形が入ります。書いておくと、レビューする人が見やすくなります。
  4. レビューをお願いする人・下書きにする（まだ見てほしくないとき）

ブランチは GitHub にあるものから選びます。まだプッシュしていないブランチは、先にプッシュします。

作業タブの流れとのつながり

作業タブの流れは Issue → ブランチ → 変更 → コミット → プッシュ → プルリク → マージ → 完了 です。ブランチをプッシュすると プルリクを作る…、プルリクを出すと #12 を開く（レビュー・マージ）、マージされると 完了 と main に戻って最新にする（git switch main → git pull）が出ます。既定のブランチ（main）で直接コミットしたときは、プルリク・マージの段はとばします。

Actions

Actions は、プッシュやプルリクのたびに、GitHub がテストやビルドを自動で動かすしくみです（.github/workflows/*.yml に書きます）。サイドバーの ▶️ Actions では、直さなければいけないものを、直す順に積んで見せます。サイドバーの赤い数は、🔴 すぐ直す と 🟠 早めに の数です。

はじめに 1 回（持ち主・リーダー）

「GitHub でログイン」で使うときは、GitHub の Life Manager に「Actions」（Read and write）・「Checks」「Commit statuses」（Read-only）・「Dependabot alerts」「Code scanning alerts」（Read-only）の権限がいります。持ち主が、GitHub の Installed GitHub Apps → Life Manager App で権限の更新を承認します。

  • 非公開のリポジトリでは、Actions の山のいちばん上に、今月このリポジトリで動いた時間の目安（最近の 100 回から。本当はこれより多めに数えられます）と、使った時間を見る（GitHub の Billing）が出ます。
  • 公開のリポジトリは無料なので、書き込める人なら確かめなしで、もう一度・手で実行ができます。
  • ひな形のワークフローには、節約の設定が入っています: timeout-minutes（ふつう 15 分でうち切る。書かないと 6 時間まで待ちます）と、concurrency（同じブランチに続けてプッシュしたら、前の実行を止める）。

Unity・Unreal のテスト

どこで動くか先に GitHub で準備すること
Unity（Unity Test Framework の EditMode・PlayMode）GitHub のパソコン（GameCI の unity-test-runner）。テストがなくても、スクリプトのコンパイルエラーに気づけます。1 回目は Unity の用意に 10〜20 分ほどリポジトリの Settings → Secrets and variables → Actions に UNITY_LICENSE（Unity Hub で Personal を有効にすると C:\ProgramData\Unity\Unity_lic.ulf にできる、その中身）・UNITY_EMAIL・UNITY_PASSWORD。チームのリポジトリでは、書き込める人はワークフローを通して秘密を取り出せるので、テスト用に別の Unity のアカウントを作ります

失敗したときの「何をすればよいか」には、Unity なら Test Runner、Unreal なら Session Frontend の Automation で、手元で同じテストを動かす方法が出ます。

リリース

リリースは「この版をみんなに配る」印です。コミットに付ける名前（タグ。例: 1.0.0）に、何が変わったか（ノート）と、配るファイル（インストーラーなど）をまとめます。サイドバーの 🏷️ リリース で、左に一覧（最新・試用版・下書き）、右にノートと添えたファイル（大きさ・ダウンロード数）が出ます。

チームで使う（管理者向け）

リーダーが、メンバーのトークンを作って配らないでください

トークンは、作った人の「合鍵」です。人のトークンを使うと、だれが操作したかが分からなくなり、その人のほかのリポジトリまで触れてしまいます。メンバーはそれぞれ、自分の GitHub アカウントで GitHub でログイン します。リーダーがすることは、リポジトリに Life Manager を入れて、メンバーを招待することだけです（「だれが何をするか」）。

リーダー: メンバーを招待する

  1. チームのリポジトリに Life Manager を入れます（一度だけ）。セットアップで チームを作る を選び、使用するリポジトリを選ぶ（入れてあれば 設定 → トークン の リポジトリを追加する）で GitHub が開きます（画面の名前は「Life Manager App」。あなたのアカウントを選んだ状態）。そのリポジトリを選んで Install（2 回目からは Save）を押します。セットアップの 作って、メンバーを招待する で作ったリポジトリは、そのまま使えます。入れていないリポジトリは、メンバーが参加しても使えません。
  2. 設定 → 接続 の 案内をコピー で「参加の案内」をコピーして、メンバーに送ります（チャット・メール・授業のページなど）。
  3. メンバーから、GitHub の名前が届きます（メンバーのアプリの画面に大きく出ています）。
  4. 設定 → 接続 の「招待する」に、届いた名前をまとめて貼り、招待を送る を押します（「設定」）。招待できるのは、リポジトリの管理者です。
  5. 「送った招待」で、まだ受けていない人が分かります。7 日で切れたら 送り直す。

メンバーとして参加する

  1. GitHub のアカウントがなければ、セットアップの GitHub で作る から作ります（「初期セットアップ」）。
  2. ログインしたら 招待を受ける を選び、画面に出る「あなたの GitHub の名前」をリーダーに伝えます。
  3. 招待のメールが届いたら「View invitation」→「Accept invitation」を押します（リーダーから届いたリンクを開いても同じです）。セットアップの「招待を受ける」では、アプリが自分で気づいて「○○ に参加しました」と出るので、このリポジトリではじめる を押します。使い始めたあとに参加したリポジトリは、左上のリポジトリの ＋ リポジトリを追加… → GitHub にある の一覧から選びます。
  4. チームのリポジトリが出てこないときは、リーダー（組織なら組織の持ち主）に、そのリポジトリへ Life Manager を入れてもらいます（最初の一度だけ）。

Organization を使う（おすすめ）

2 人以上で続けて使うときは、GitHub の Organization（無料）がおすすめです。人ではなく Organization がリポジトリを持つので、人が抜けても残り、権限をチーム単位で管理できます。

  1. Organization を作ります（Settings → Organizations → New organization、Free プランで可）。
  2. Organization の中にリポジトリを作ります（Private がおすすめ）。
  3. メンバーを招待し（Organization Settings → Members → Invite member）、Write 以上の役割を付けます。
  4. Life Manager を組織に入れます（一度だけ）。組織の持ち主が、アプリの 使用するリポジトリを選ぶ の下の「組織に入れるときは こちら」で GitHub を開き、組織を選んで、使うリポジトリを選び Install します。メンバーはログインするだけで使えます。

個人のリポジトリで使うときは、持ち主が自分のアカウントに Life Manager を入れてリポジトリを選び、設定 → 接続 から招待します（GitHub の Settings → Collaborators → Add people でも同じです）。

トークンで使うときの注意

Fine-grained token でリポジトリを選ぶとき、出てくるのは「自分が持ち主のリポジトリ」と「入っている Organization のリポジトリ」だけです。ほかの人の個人リポジトリに招待された場合は出てきません。そのときは GitHub でログイン を使うか、Organization に移します。トークンは、プロジェクト専用のトークン → いつものトークン の順に使われます。

  2. 作業タブで Issue を選び、Issue 用のブランチ（issue-12 など）を作る。

  4. 作業タブの プルリクを作る… でプルリクを作り、チームの人が「変更されたファイル」を見てレビューする。よければマージする（説明に Closes #12 があれば、Issue が自動で閉じる。「プルリク」）。

「GitHub でログイン」をすすめる理由

ログインなら、Life Manager が触れるのは 持ち主が選んだリポジトリだけで、鍵は 8 時間ごとに新しくなり、PC ごとの期限（30 日〜半年）で切れます。組織では、持ち主が Life Manager を一度入れるだけです。トークン（Fine-grained token）で入ると、組織のはじめの設定では トークン 1 本ごとに持ち主の承認がいり、期限（アプリが開く作成ページでは 90 日）が来るたびに、作り直しと承認がまた必要です。ほかの人の個人のリポジトリは Fine-grained token では選べず、届いた招待もアプリの中では受けられません。

設定

設定は、上のタブで「接続」「タスク」「通知」「表示」「トークン」「その他」に分かれています。

トークン

  • GitHub トークン: いつものトークン（だれとしてつながっているか・種類・期限・使えるか）と、プロジェクトごとに、どのトークンを使っていて使えるかが見えます。
    • ログインし直す（期限を延ばす） / トークンを入れる…: いつものトークンを入れ替えます（ログインし直すと、この PC で使う期限も今日から数え直します）。確かめる: もう一度確かめます。
    • 使用するリポジトリを選ぶ / リポジトリを追加する（ログインしているとき）: GitHub が開き、Life Manager に使わせるリポジトリを選ぶ・足すことができます。足すと、アプリが自分で気づきます。「すべてのリポジトリ」に入れてあるときは、ボタンは出ません。
    • プロジェクトの行の 専用のトークンにする…: そのプロジェクトだけ別のトークンを使います（別のアカウントのリポジトリなど）。いつものに戻す で外せます。使うトークンは「このプロジェクト専用 → いつもの」の順に決まります。
    • 🔴 や 🟡 のときは 直し方 を押すと、何をすれば直るかと、そのページを開くボタンが出ます。
    • ログアウト: この PC から、あなたのトークンをすべて消します（学校の PC などで使い終わったとき）。使うリポジトリの一覧はあなたの分としてしまうので、次に使う別の人には出ません（あなたがもう一度ログインすれば、続きから使えます）。ほかのアカウントが残っていなければ、最初のセットアップの画面になり、GitHub での許可も取り消すときの案内が出ます。

ログアウトは、左下のアカウントのメニューからもできます。

接続

今のリポジトリのチーム（招待・メンバー）をまとめています。リポジトリの追加・切り替え・この PC のフォルダは、左上のリポジトリから行います（上の ＋ リポジトリを追加… からも開けます）。

  • 参加の案内（管理者）: メンバーに送る文（ダウンロード先・ログイン・名前を伝える・招待を受けるリンク）を 案内をコピー でコピーして、チャットなどに貼ります。
  • 招待する（今のリポジトリの管理者だけ）: メンバーから届いた GitHub の名前を、改行・カンマ・空白で区切って何人でも貼り、招待を送る。1 人ずつ「招待しました」「もうこのリポジトリを使えます」「その名前の人は GitHub にいません」などの結果が出ます。うまくいかなかった名前は欄に残るので、直して送り直せます。組織のリポジトリでは権限（書き込み・運営・整理・読むだけ・管理）を選べます。
  • 送った招待（管理者だけ）: まだ受けていない招待。リンクをコピー（招待を受けるページの URL。チャットで送る用）・取り消す。招待は 7 日で切れ、切れたものは 送り直す。
  • メンバー: このリポジトリを使える人と権限。管理者は、行の 外す → その行に出る確かめで 外す を押すと、メンバーから外せます（持ち主と自分の行には出ません）。外した人は、このリポジトリを使えなくなります（書いた Issue やコメントは残ります）。もう一度招待すれば戻せます。組織のリポジトリで、組織のメンバーとしてまだ使える人は、組織の画面（People・Teams）で外します。
  • 管理者でないときは、リーダーに伝える自分の名前（コピー）が出ます。
  • 自分で作ったトークン（Fine-grained token）で入っているときは、招待する・送った招待を見る・取り消すのに、トークンの「Administration」の権限（Read and write）がいります。足りないときは、その旨と直し方が出ます（GitHub でログイン なら要りません）。
  • あなた宛ての招待（下のほう）: トークンで入ったときなど、アプリから見える招待が出ます（断る、組織への招待は GitHub で参加）。「GitHub でログイン」では、まだ参加していないリポジトリの招待はここに出ないので、メールの View invitation から受けます。

つながらないとき（オフライン）

電車の中など、インターネットにつながらないところでも、最後に読み込んだ Issue・設定・日誌を見たり、変えたりできます。変えた内容はこの端末に置いておき（送信待ち）、つながったら順に GitHub に送ります。

つながらないあいだにできること

  • Issue・メモを作る。タイトル・本文・ラベル・担当者・マイルストーンを変える。閉じる・開き直す。コメントする。
  • ルーチン・通知スケジュール・イベント通知・リマインダー・ボードの設定を保存する。
  • 日誌のノートを保存する（一度開いたことのある日誌だけ）。日誌の作成は、つながってから行われます（夜の自動作成も同じ）。
  • リマインダーと通知スケジュールの OS の通知 は、つながらないあいだも出ます。ルーチンの Issue も、決めた時刻に送信待ちとして作られます。

送るのは、つながったとき（送っていない変更があるあいだは、アプリが 30 秒ごとに確かめます）か、今すぐ送る を押したときです。Discord などへのお知らせも、GitHub に送れたときに、送れたあとの番号で出します。

ラベル・マイルストーンの作成・変更は、つながっているときに行ってください。

GitHub 側でも変えられていたとき

送る前に、GitHub の今の内容と比べます。まとめられるものは、自動でまとめます。

  • ラベル・担当者・リマインダーは、足したもの・外したものだけを当てるので、両方の変更が残ります。
  • 本文・日誌のノートは、git のマージと同じように行ごとに比べます。別々の行を変えていれば、両方の変更が残ります。チェックボックスの付け外しだけなら、GitHub 側の新しい本文に同じ付け外しをします。
  • 同じところを両方で別の内容に変えていたときは、確認 に並びます。

確認 を開くと、ぶつかったところを 1 件ずつ見せます。

よくある質問・困ったとき

上の「未送信」がなかなか消えません
まだ GitHub につながっていないか、トークンが無効になっているかもしれません。未送信 を押すと、送れなかった理由が出ます。トークンが無効のときは、設定 → トークン で、ログインし直すかトークンを入れ直してください（「つながらないとき」）。
「git が見つかりません」と出ます
Git が入っていません。設定 → その他 の「この PC の git」の Git をインストールする… から入れてください。入れたあとも見つからないときは、アプリを開き直してください。
プッシュやプルで「GitHub へのログインが必要です」と出ます
この PC の git が、まだ GitHub にログインしていません。Windows では、はじめてのプッシュのときにログインの画面（ブラウザ）が出ることがあります。出ないときは、その他 ▾ → このフォルダでターミナルを開く で、同じ操作（git push など）を一度打ってログインしてください。
プッシュが「拒否された（rejected）」と出ます
GitHub の方に、まだ取り込んでいないコミットがあります。先に ⬇ プル で取り込んでから、もう一度プッシュしてください。
コミットできません
コミットするファイルにチェック（ステージ）が入っているかを確かめてください。「名前とメールアドレスが決まっていません」と出るときは、設定 → その他 の「この PC の git」の 使う準備を確かめる から決めてください。
作業フォルダに選べません
選べるのは、そのリポジトリをクローンしたフォルダだけです。まだ PC にない場合は、左上のリポジトリの ⋯ → この PC にクローンする… を使ってください。
学校の PC で Git がインストールできません
インストールには PC の管理者の確認が必要です。PC の管理者に Git のインストールを頼んでください（https://git-scm.com/downloads）。
データはどこに保存されますか？
すべて GitHub のリポジトリ（Issue・マイルストーン・ラベル）に保存されます。ルーチンや通知の設定は、リポジトリの config/ フォルダに保存されます。アプリを消しても、データは GitHub に残ります。作業フォルダの場所や表示の設定は、この PC だけに保存されます。
画面の上に「トークンの期限が…」「トークンが使えません」と出ます
設定 → トークン で、GitHub でログインし直す（トークンで使っているときは トークンを入れる…）を押してください。プロジェクト専用のトークンなら、その行の 入れ替える… から入れ直します。GitHub でログインした場合は、この PC で使う期限（30 日・90 日・半年）が近づくと知らせが出ます。ログインし直す（期限を延ばす） を押すと、今日から数え直します。
学校の PC で使い終わったら？
左下のアカウントを押して ログアウト（か 設定 → トークン の ログアウト）を押してください。この PC から、あなたのトークンがすべて消えます。GitHub 側でもやめたいときは、GitHub の Settings → Applications → Authorized GitHub Apps から Life Manager App を取り消します（ログアウトのあとの画面にも案内が出ます）。
チームのリポジトリが一覧に出てきません
招待を受けているか（メールの「Accept invitation」）、リーダー（組織なら組織の持ち主）がそのリポジトリに Life Manager を入れているかを確かめてください（「チームで使う」）。URL を貼って選ぶと、何が足りないかが出ます。
複数のリポジトリを使えますか？
使えます。左上のリポジトリの ＋ リポジトリを追加… で足し、同じ一覧から切り替えます。作業フォルダも、リポジトリごとに（一覧の ⋯ から）決められます。
ガントチャートに帯が出ません
Issue の詳細の 設定 のタブの 日程 で、開始日と終了日を決めてください。見積もりを付けるだけでも、仮の帯（点線）で出ます（「見積もりから仮の日程を置く」）。
オフラインで使えますか？
使えます。つながらないあいだも、最後に読んだ内容を見られ、Issue の作成・変更・コメントは送信待ちになって、つながったら送られます（「つながらないとき」）。git の作業（ステージ・コミットなど）は PC の中で行えますが、プッシュ・プル・フェッチには接続が必要です。
スマホに Discord の通知が届きません
Android の電池の節約で、Discord の知らせが止められていることがあります。スマホの Discord の設定で、電池の使い方を「制限なし」にしてください。PC の Discord を開いたままだと、スマホへの知らせが出ないこともあります（PC の Discord を閉じると届きます）。

git のことば

リポジトリ repository
ファイルと、その変更の記録（履歴）をまとめたもの。GitHub にあるものと、PC にクローンしたものがあります。
クローン git clone
GitHub のリポジトリを、履歴ごと PC にコピーすること。
コミット git commit
変更を、要約を付けて履歴に記録すること。記録した 1 つ 1 つもコミットと呼びます。
ハッシュ
コミットごとに付く番号（799773a のような英数字）。
ステージ git add
次のコミットに入れる変更を選ぶこと。選んだ変更の置き場所もステージ（インデックス）と呼びます。
.gitignore
git で記録しない（無視する）ファイルを、1 行に 1 つ書いておくファイル。すでに記録しているファイルには効かないので、git rm --cached で管理から外します。
差分 diff
変更の中身。追加した行と削除した行で表します。
ブランチ branch
作業を分けて進めるための流れ。ブランチは、その流れの先頭のコミットを指す「しおり」のようなものです。
既定のブランチ
GitHub で最初に表示されるブランチ（多くは main）。完成したものをまとめる場所として使います。
HEAD・チェックアウト git switch
今作業しているブランチ（コミット）が HEAD です。ブランチを切り替えることをチェックアウトと呼びます。
切り離された HEAD
ブランチではなく、コミットそのものを取り出している状態。ここでコミットしても、どのブランチにも属しません。続けて作業するなら、ブランチを作ります。
マージ git merge
別のブランチの変更を、今のブランチに合流させること。
プルリク（プルリクエスト） pull request
「このブランチの変更を main に入れてください」という GitHub の上のお願い。変更を見て（レビュー）、よければマージします。
レビュー
ほかの人の変更を見て、承認したり、直してほしいことを伝えたりすること。
リベース git rebase
今のブランチのコミットを、別のブランチの先に作り直すこと。履歴が一直線になりますが、コミットは作り直されます。
チェリーピック git cherry-pick
ほかのブランチの特定のコミットだけを、今のブランチに取り込むこと。
リバート git revert
あるコミットの変更を打ち消す、新しいコミットを作ること。履歴は消しません。
リセット git reset
ブランチを前のコミットまで戻すこと。後のコミットはブランチから外れます。
競合（コンフリクト）
同じところが両方で変わっていて、git が自動でまとめられない状態。
退避（スタッシュ） git stash
コミットせずに、変更を一時的にしまっておくこと。
タグ git tag
コミットに付ける名前。リリースの区切り（v1.0.0 など）に使います。
リモート・origin
GitHub など、PC の外にあるリポジトリ。クローン元には origin という名前が付きます。origin/main は「GitHub にある main の位置（最後にフェッチしたとき）」です。
上流ブランチ
プッシュ・プルの相手になる、GitHub のブランチ。
フェッチ・プル・プッシュ
フェッチは GitHub の最新の状態を取ってくるだけ、プルは取ってきて今のブランチに取り込む、プッシュは自分のコミットを GitHub に送ることです。
amend
直前のコミットを作り直して、変更や要約を直すこと。
空コミット
ファイルの変更を含まないコミット（git commit --allow-empty）。
Issue
GitHub で管理する「やること」や課題。Life Manager ではタスクとして扱います。
